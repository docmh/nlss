# SEM (Lavaan, NLSS format)

## Overview

Run SEM/CFA/path/mediation models with lavaan and produce NLSS format tables and narrative text. Supports multi-group models, robust estimators, bootstrap CIs, and invariance sequences.

## Assistant Researcher Model

NLSS assumes a senior researcher (user) and assistant researcher (agent) workflow. Requests may be vague or jargon-heavy; the agent should inspect the data, ask clarifying questions before choosing analyses, document decisions and assumptions in `scratchpad.md`, and produce a detailed, NLSS format-aligned, journal-alike report.

## Core Workflow

1. Identify the input type (CSV, RDS, RData data frame, Parquet, or interactive).
2. Provide a lavaan model (`--model` / `--model-file`) or use a builder (`--factors`, `--dv`/`--ivs`, or `--x`/`--m`/`--y`).
3. Choose estimator, missing handling, SE/CI, and fit indices.
4. Run the `sem` operation through `run_nlss.R` with the correct flags.
5. Review the run's requested/effective inference, fit status, cases and warnings.
6. Use its numerical evidence to write a context-sensitive response. Deterministic
   statistical output is not a final research report or a mandatory narrative template.

## Execution: `sem`

Use the [shared launcher](../../SKILL.md#rscript-execution-required); `<skill>`
is the installed NLSS skill directory.

### CSV Input

```bash
Rscript "<skill>/scripts/R/run_nlss.R" sem --csv <path to CSV> --analysis sem --model "y ~ x1 + x2"
```

### Parquet Input

```bash
Rscript "<skill>/scripts/R/run_nlss.R" sem --parquet <path to parquet> --analysis cfa --factors "F1=item1,item2;F2=item3,item4"
```

### Interactive Prompts

```bash
Rscript "<skill>/scripts/R/run_nlss.R" sem --interactive
```

## Options

Defaults are loaded from `scripts/config.yml` (requires R package `yaml`); CLI flags override config values.

### Inputs

- `--csv`, `--sav`, `--rds`, `--rdata`, `--df`, `--parquet`: standard inputs (see shared workflow).
- `--sep`, `--header`: CSV parsing; defaults from `defaults.csv.sep` and `defaults.csv.header`.

### Model Selection

- `--analysis`: `sem`, `cfa`, `path`, `mediation`, or `invariance` (default: `modules.sem.analysis`).
- `--model`: lavaan syntax in a quoted string.
- `--model-file`: path to a lavaan syntax file.
- `--paths`: alias for `--model` (convenience for path models).
- `--factors`: CFA builder string: `F1=item1,item2;F2=item3,item4`.
- `--dv` and `--ivs`: path builder (`dv ~ iv1 + iv2`).
- `--x`, `--m`, `--y`: mediation builder (`--m` supports multiple mediators).
- `--covariates`: optional covariates added to mediator/outcome equations.
- `--serial`: serial mediation (currently supports two mediators; default `modules.sem.serial`, false).

### Grouping and Invariance

- `--group`: multi-group variable.
- `--group-equal`: lavaan `group.equal` constraints.
- `--invariance`: steps for invariance (default: `modules.sem.invariance`), e.g. `configural,metric,scalar,strict`.
- `--analysis invariance` requires `--group`.

Group labels follow lavaan's actual fitted group order (normally first appearance),
not alphabetical factor levels. Review this order before interpreting vector labels
such as `c(a,b)*x`. A single parameter label shared across groups imposes equality;
this also applies to labels generated by the mediation builder. Use explicit model
syntax with group-specific labels when distinct indirect effects are intended.
The full parameter specification and lavaan warnings preserve these constraints.

The built-in scalar/strict sequence uses **continuous-indicator intercept**
constraints. It must not be interpreted as an ordinal scalar/strict test. With
ordered indicators those automatic steps are rejected; use an explicitly justified
custom model/`--group-equal` specification (including thresholds as appropriate).
Configural/metric steps retain their explicit loading constraints, but choosing
valid ordinal identification and comparable models still requires methodological
judgment. No automatic pass/fail decision or new categorical invariance method is added.

### Estimation

- `--estimator`: ML, MLR, MLM, MLMV, MLMVS, WLSMV, ULSMV, DWLS, ULS, GLS (default: `modules.sem.estimator`).
- `--missing`: `fiml`, `listwise`, `pairwise` (default: `modules.sem.missing`).
- `--se`: `standard`, `robust`, `bootstrap` (default: `modules.sem.se`).
- `--ci`: `standard`, `bootstrap`, `bca` (default: `modules.sem.ci`).
- `--conf-level`: confidence level (default: `modules.sem.conf_level`).
- `--bootstrap`: enable bootstrap SEs/CIs (default: `modules.sem.bootstrap`).
- `--bootstrap-samples`: resamples (default: `modules.sem.bootstrap_samples`).
- `--seed`: non-negative R integer; bootstrap uses `modules.sem.seed` (default 1) when omitted.
- `--ordered`: declare ordinal indicators not already stored as ordered factors.
  Numeric category identity is matched before display conversion, so distinct
  close floating-point codes remain separate. Existing ordered factors keep
  their declared order. This fixes the separately documented Phase-2 ordinal
  conversion edge case; relevant earlier fits should be rerun.

Numeric SPSS value labels remain metadata. `--ordered` uses the underlying numeric
code order, not the alphabetic order of label text. Existing ordered factors retain
their declared levels; explicit numeric grouping preserves distinct double values.
Inf/-Inf in selected variables are errors. Ordinary missing values follow the actual
lavaan estimator/missing/fixed-exogenous-variable rules, with retained/excluded
source rows and coverage recorded per fitted group. FIML is not automatic recovery
of missing fixed exogenous variables, nor multiple-imputation pooling.

Invalid option domains or incompatible lavaan combinations fail explicitly rather
than silently selecting another estimator or missing-data method. Requested robust
estimator names can resolve internally to ML/DWLS plus a particular SE and test;
the output records these effective lavaan settings separately. Fit-index names are
explicit: for example `cfi`, `cfi.scaled` and `cfi.robust` are different outputs and
are not silently substituted for each other. Unknown or unavailable requested fit
indices cause an explicit failure; finite values and unavailable numeric cells are
distinguished in the result.

`--bootstrap TRUE` or `--se bootstrap` activates resampling. Bootstrap/`bca` CIs
require that activation; no analytic fallback is allowed. `--ci standard` with
bootstrap SEs uses lavaan's normal bootstrap interval (`norm`, including bootstrap
bias correction); `--ci bootstrap` uses percentile intervals. For compatibility,
`--ci bca` means lavaan `bca.simple`: bias correction **without acceleration**, not
full BCa. Failed and nonadmissible bootstrap draw counts/indices and the effective
seed are recorded. Finite nonadmissible draws remain in lavaan's SE/CI calculations;
the reported successful count does not imply all draws were admissible.

### Reporting

- `--std`: `none`, `std.lv`, `std.all` (default: `modules.sem.std`).
- `--fit`: fit indices list (default: `modules.sem.fit`).
- `--r2`: report R² (default: `modules.sem.r2`).
- `--modindices`: modification index cutoff (default: `modules.sem.modindices`).
- `--residuals`: include standardized residuals in the saved result (default: `modules.sem.residuals`).
- `--digits`: rounding (default: `defaults.digits`).
- `--template` selects a template key or file path for NLSS format outputs (falls back to defaults).
- `--log`: Optional standalone logging; project evidence remains enabled (default: `defaults.log`).
- `--user-prompt`: original AI prompt for logging.

## Outputs

The mandatory [run contract](../run-contract.md) publishes `.nlss/runs/<id>/request.json`,
`result.json` and deterministic `output.md`, with frozen templates. External model
files are resolved into saved model text; exact replay does not reread a mutable
model file. `--log FALSE` disables only the optional standalone log.
Standalone semantic `report_<YYYYMMDD>_<metaskill>_<intent>.md` files remain metaskill
outputs, freely structured around the research question.

Outputs in a current project follow the [shared run contract](../run-contract.md):
`.nlss/runs/<run-id>/` holds request/result/output and artifacts; the automatic
`report_canonical.md` stays at the project root. No additional project JSONL log
is produced. `--log` affects optional standalone logging, not this evidence.

- `report_canonical.md`: NLSS format report containing analysis type, table, and narrative text.
- `result.json`: Machine-readable results and options, always retained in the saved run.
- The JSON result retains all parameter estimates, the lavaan parameter
  specification (including fixed/free/equality information), fit indices, R²,
  requested modification indices/residuals, case selection and inference status.
  Existing `params_df` path-table keys remain compatible; supplementary Markdown
  reports the same fit's variances, intercepts and thresholds.
- Nonconverged fits fail without publishing normal output. Converged but
  inadmissible solutions (including negative variances) retain conspicuous status
  and warnings, not a claim of model validity. Unavailable optional diagnostics or
  intervals are marked, never fabricated. Each invariance step has its own audit.

## NLSS format Template (YAML)

Templates live under `assets/sem/` and are selected via `templates.sem.*` in `scripts/config.yml`.

- Default SEM: `templates.sem.default` -> `sem/default-template.md`
- CFA: `templates.sem.cfa` -> `sem/cfa-template.md`
- Mediation: `templates.sem.mediation` -> `sem/mediation-template.md`
- Invariance: `templates.sem.invariance` -> `sem/invariance-template.md`

Templates use YAML front matter with `{{token}}` placeholders. Supported sections:

- `table.columns`: ordered column definitions (`key`, optional `label`, optional `drop_if_empty`).
- `note.template`: overrides the note text (defaults to `{{note_default}}`).
- `narrative.template` or `narrative.row_template`: overrides narrative text.

### Table Column Keys (SEM/CFA/Mediation)

`group`, `path`, `label`, `est`, `se`, `z`, `p`, `ci_low`, `ci_high`, `std`

### Table Column Keys (Invariance)

`step`, `group_equal`, `chisq`, `df`, `p`, `cfi`, `tli`, `rmsea`, `srmr`, `delta_cfi`, `delta_rmsea`

### Note Tokens

`note_default`, `fit_summary`, `r2_summary`, `indirect_summary`, `estimator`, `missing`, `se`, `ci`

### Narrative Tokens

`narrative_default`, `fit_summary`, `r2_summary`, `indirect_summary`

## NLSS format Reporting Guidance

- Report fit indices (chi², df, CFI, TLI, RMSEA, SRMR) and the estimator/missing handling used.
- For mediation, report indirect effects with bootstrap CIs and note the model type (parallel vs serial).
- For CFA, report standardized loadings and factor correlations if relevant.
- For invariance, report the explicit constraints and adjacent-step delta
  CFI/RMSEA; their interpretation depends on design, measurement level and theory.
  Deltas alone are not a significance test or an automatic finding of invariance.
- Interpret latent constructs, competing models, model modifications and mediation
  against substantive theory and study design. A fitted mediation path does not by
  itself establish causation. Templates structure statistical evidence, not these
  semantic judgments or the final report's organization.
