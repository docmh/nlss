# Project Inspect

Use for “Where are my results?” or “What is in this project?”, including from a
subfolder. Inspection is optional, not a prerequisite for opening a report or
reading a user-supplied study document. It never creates or converts a project.

## Command and options

```bash
Rscript scripts/R/project_inspect.R --project /path/to/study
Rscript scripts/R/project_inspect.R --project /path/to/study --verify TRUE --format json
```

- `--project DIR|MARKER`: explicit selection. Missing/invalid selection fails
  without fallback. Omit it for nearest-ancestor discovery, never children or
  siblings. Nested markers form boundaries.
- `--verify TRUE|FALSE`: compare registered data/dictionary/source bytes with
  recorded hashes. Default FALSE: paths and sizes only. This does **not** verify
  run/report dependencies, semantic correctness or protocol freshness.
- `--format markdown|json`: stdout format, default Markdown.
- `--help`: usage. Unknown/repeated flags and invalid values fail.

Defaults: `scripts/config.yml` under `modules.project_inspect`.
Only the current schema-2 / `managed_parquet_v1` marker is supported; there is
no older-layout reader or conversion. No note switch, discovery or fingerprint:
user documents are ordinary files read when supplied by the researcher.

## What the view shows

The first result link is the default root **`report_canonical.md`**. It is
automatically maintained by execution, not regenerated by inspection.

- Registered datasets: visible working file, original/preserved source,
  descriptor, initial data/dictionary version and availability.
- `.nlss/runs/` and `.nlss/utility-runs/`: procedure, recorded dataset/version
  (or parameter-only/utility input), recorded status, and links to output,
  request and result. Pending directories are never presented as completed.
- `.nlss/reports/<report-id>/`: saved revisions, saved time, selected visible
  report and preserved Markdown/descriptor links. No automatic “latest” choice.

Recorded completion is **not** verified integrity or replayability. Missing,
incomplete, malformed and oversized records remain qualified individually rather
than hiding neighbouring results. A missing visible report does not erase its
preserved revision. Working hashes, when requested, are compared with the
registered **initial** version, not an inferred latest version; a difference
alone does not establish corruption or who edited the file.

For explicit historical dependency verification use
[project-report](project-report.md), not routine project browsing.

## Read-only boundary and links

Read only the marker, registered dataset metadata and bounded run/report
directory candidates. Each metadata file is limited to 2 MiB; larger records
are labelled `metadata_too_large`, not silently truncated. Saved object contents
and unrelated files are not scanned. No Parquet/RDS loading, execution, locks,
new index, logs, copies, snapshots or background refresh.

Outside-project paths are classified without reading them. Symlinks, special
files and nested projects are not traversed. JSON paths stay project-relative.
Markdown printed to stdout uses encoded, root-anchored local links, including
spaces and non-ASCII names; this remains useful from another working directory
and after moving the whole project. Missing/unsafe targets are shown as status
text, not functioning links. Existing report bytes are not rewritten.

Exit 0 means inspection ran, not that an integrity audit passed. Invalid required
metadata/selection fails with exit 2. Concurrent edits are not an atomic snapshot.
Redirect stdout only to an explicitly chosen destination without overwriting a
user document. No automatic relinking, repair, reconciliation, report authoring,
archive export, cleanup or total/reclaimable-storage estimate.

Dependencies: `yaml`, `jsonlite`, `digest`, shared bootstrap and, on Unix,
the standard `test` command for distinguishing regular files from devices/FIFOs.
No Arrow is needed.
