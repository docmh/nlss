# Phase 2 compatibility inventory

This is a migration inventory, not a claim that every statistical procedure has been independently certified. All 26 pre-existing R entrypoints remain present. All original entrypoints now use the mandatory bootstrap and a suitable boundary: statistical runs, utility/lifecycle evidence or standalone history readers. Final acceptance results are recorded separately from this capability inventory.

## Contract boundary

- **Contract:** centralized mandatory bootstrap plus the Phase 2 run/result contract. Numeric tables remain generated by R; semantic synthesis remains an agent task grounded in those tables and run references.
- **Utility audit:** resolved request/results, artifact hashes and protected compatibility projections, without a fabricated dataset or statistical replay. See [utility contract](utility-contract.md).
- **Standalone history:** strict shared positional compatibility adapter, with read-only inspection or protected reconstruction exports. Report reconstruction does not refit a statistical model.
- **S / D / G:** coverage exists in the shared smoke suite / a dedicated module runner / numeric golden artifacts under `tests/values/`. These labels inventory test assets, not the results of the latest test run. `tests/tests.yml` is the executable source of truth.
- **Phase 2 tests:** new contract/configuration/replay/MI acceptance checks supplement existing tests. Unsupported combinations must fail explicitly; no module is removed because it has not yet migrated.

## Phase 2 additions

| Entrypoint | Responsibility | Boundary |
|---|---|---|
| `mi_regression.R` | Fit a supported regression separately in each preserved imputation and pool model estimates and uncertainty. | New contract; Gaussian identity, binomial logit/probit/cloglog, Poisson log only. |
| `replay_run.R` | Verify a recorded contract and rerun a supported deterministic analysis. | Only migrated contracts; not an automatic replay adapter for every legacy log. |

Power additionally supports parameter-only schema-2 runs in `planning/runs/`,
without a dataset reference. Dataset-backed runs retain schema 1. This bounded
input kind does not migrate `metaskill_runner`, change project discovery, or
grant data-free/replay support to other legacy entrypoints.

The MI entrypoint uses the preserved `mids` source, not the averaged/mode-completed columns written by `impute.R`. It requires at least two imputations, compatible fit terms/rows/levels/degrees of freedom across imputations, and finite successful fits. Model warnings, singular fits and non-convergence must not silently produce a pooled result.

The initial MI scope deliberately excludes mixed models, SEM, survival, survey-weighted models, arbitrary formula calls/transforms, `.` expansion, weights, offsets, subsets and multivariate responses. Plain column formulas with `+`, `-`, `*`, `:`, parentheses and intercept selection are supported. GLM coefficients are pooled on their link scale. Other existing modules continue to operate on a single explicit dataset and must not be described as pooled MI inference. Extending MI support requires a separate, independently tested model/pooling adapter.

## CLI compatibility

Phase 3 adds the standalone [project-inspect](utilities/project-inspect.md)
entrypoint (`project_inspect.R`). It uses the shared parser with an explicit
`help project note verify format` option allowlist, bypasses legacy discovery for
read-only inspection, and creates no audit bundle or workspace. Its dedicated
tests are registered as `tests.scripts.phase3_r`; no statistical coverage or
existing entrypoint is removed. Legacy analysis discovery/publication remains
unchanged until the subsequent storage transition.

The authoritative allowed-option registry is `cli_module_options()` / `cli_option_schema()` in `scripts/R/lib/cli.R`. Phase 1 tests compare literal `opts` accesses against that registry. Names below are written without the `--` prefix; aliases are retained.

Shared registered options: `help interactive log template user-prompt`. Ordinary dataset-oriented entrypoints additionally accept `csv sav rds rdata parquet df sep header dataset-name import-action csv-decimal csv-encoding csv-col-types csv-na-values`. This shared registration does not imply that every common option has meaningful behavior for every utility: consult each entrypoint's `--help` and reference for its input/output semantics. `calc`, `research_academia` and `mi_regression` do not receive source-import flags. MI regression requires a preserved `--mids` artifact and rejects interactive mode.

Options accept both `--name value` and `--name=value`. Unknown or duplicate options, missing values and malformed Booleans are errors in the shared parser. `check_integrity.R` retains positional `<analysis_log.jsonl> [--diagnose TRUE|FALSE]`; `reconstruct_reports.R` retains positional `<analysis_log.jsonl> [--out-dir PATH]`. Their shared positional adapter rejects unknown/duplicate flags, malformed Booleans and missing values; reconstruction adds explicit `--overwrite TRUE|FALSE`. Diagnostic aliases and split Windows-drive paths remain supported. An explicit missing path no longer silently selects an environment-fallback log.

## Package and fallback inventory

- **Shared configuration:** `yaml` is required. There is no hidden R-list default fallback. `scripts/config.yml` is the developer-owned canonical defaults and type-shape source; user/site changes should be expressed as a partial `NLSS_CONFIG_PATH` override. Unknown override keys, wrong scalar types and invalid/empty YAML are rejected. Editing the canonical schema itself is a source change and needs review/tests.
- **Dataset import/versioning:** `arrow`, `digest` and `jsonlite` support workspace Parquet, SHA-256 and metadata/provenance. `haven` is required for SAV and for interpreting tagged haven missings. The unsafe foreign-based SPSS fallback removed in Phase 1 is not restored.
- **Base R procedures:** descriptive statistics, frequencies, correlations, crosstabs, t-tests, nonparametric tests, ordinary regression, scale/reliability calculations and simple missing-data operations retain their existing base-R paths. “Base R” here excludes the common IO dependencies needed to read/write a workspace.
- **ANOVA:** `car` is required for requested type-II/III between-subject tests; no silent Type-I fallback. `emmeans` supports requested marginal-mean contrasts. Repeated measures retain the sequential `aov(Error(...))` adapter, with requested/effective type disclosed; this is not new Type-II/III repeated-measures support. See the module reference for design and sphericity limits.
- **EFA/SEM:** `psych` is required by EFA; `lavaan` by SEM. They remain independent statistical packages, not reimplemented in the common contract.
- **Mixed models:** `lme4` and `performance` are required by the entrypoint. Requested Satterthwaite/Kenward–Roger inference requires `lmerTest`, with `pbkrtest` additionally required for Kenward–Roger. `car` supplies requested Type-II/III Wald tests without denominator-df inference; `emmeans` supplies requested marginal means/contrasts. Missing dependencies must not silently change the requested inference. Existing linear-model capabilities remain; this is not new GLMM or MI pooling support.
- **Diagnostics:** mixed/SEM paths use `lme4`/`lavaan`; `performance`, `influence.ME`, `DHARMa` and `MVN` provide selected optional checks. All five families share the run contract and disclose unavailable/skipped checks. Matching diagnostic refits to the substantive model remains essential; migration does not turn screens into blanket approval.
- **Imputation:** `mice` for the mice engine; `VIM` for KNN. The existing auto engine can choose based on availability; the resulting engine is reported. The new MI regression additionally requires `broom` for supported model tidying/pooling and does not fall back to single-completion inference.
- **Power:** `pwr` for conventional analyses and `semPower` for SEM power. Both capabilities remain.
- **Graphics/research:** Plot requires `ggplot2`; `viridisLite` supplies its viridis palette. The divergent base-graphics fallback is removed, not any plot type. Images use explicit R devices; SVG requires Cairo support, not an automatic `svglite` installation. Research discovery retains `jsonlite`, optional `curl` and the selected network APIs.
- **Legacy integrity tools:** their MD5/log-chain and compressed report reconstruction remain for old files. A legacy integrity pass is not a Phase 2 SHA-256 replay proof or a cryptographic signature.

## Completed boundaries and deliberately separate work

Phase 3 additionally offers opt-in `project_create.R` and managed persistence for
`descriptive_stats.R`/`data_transform.R`; see the
[bounded workflow](utilities/project-create.md). `project_inspect.R` reads both
layouts without writes. No legacy project or scientific method was migrated by
default, and managed report lifecycle support remains separate.

There are 21 statistical run entrypoints (including new MI regression), four
utility/lifecycle audit entrypoints and two standalone historical readers.
The additional replay utility verifies statistical saved requests. No original
entrypoint remains on a local fallback bootstrap. Utility evidence does not
promise statistical replay, and MI pooling remains limited to its validated
model families. The shared bootstrap is a small loader of ordinary functions,
not a new plugin framework, universal statistics DSL or workflow engine.
Phase 3 project-folder reorganization and later semantic-reporting/plugin work
remain separate; no current layout migration or automatic environment restore
is implied by these Phase-2 contracts.
